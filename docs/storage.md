# Storage map

What Cindy keeps on disk, who owns it in Cindy, and the chapter that ports it. The port shares
Cindy's userData folder (`Cindy`, `CindyGlobal` or `CindyDev`), so each store keeps Cindy's format.
Cindy paths are at the PRD's reference commit.

## Rules

- A store is ported in the chapter that first reads or writes it; no store code lands before its
  first caller.
- Never migrate, repair or rewrite Cindy's SQLite schema. Open a database only after Cindy's
  read-only admission passes (below).
- Each store keeps its owner's publication and locking: exclusive no-replace links, cross-process
  locks and atomic renames are ported as the owner module does them, never swapped for another.

## SQLite: `cindy-<userId>.db`

Owner: `apps/desktop/src/main/localDb/`. One file per signed-in account, so it opens after sign-in
(chapter 13). Port these files whole, not a summary of them:

1. Reader lease: `localDb/schemaMigrationLease.ts`, including `withLeaseTransition`'s per-database
   transition gate and its stale and corrupt lock recovery. Hold it until the database closes.
2. Admission: `checkMigrationCompatibility` in `localDb/migrationRunner.ts`. Schema version,
   `migration_history` and `<db>.migration-runtime.json` must match the reference commit's
   migrations, except the one-way seq-62 identity repair (`isKnownRuntimeIdentityRepair`). Any
   other mismatch refuses to open and names the issue.
3. Before writing `messages`: `registerCjkSeg` in `localDb/registerCjkSeg.ts`, which registers
   `cjk_seg` and installs its TEMP triggers, in the order that file sets.

## Other stores

Every Cindy main-process module that may persist a file (583 at the reference commit, paths under
`apps/desktop/src/main/`), by the one chapter that ports it with its exact file names, format and
publication. The list is a superset: a module that turns out to write nothing is dropped when its
chapter is expanded. Found by the union of:

- files that mention `.json` anywhere;
- files that `JSON.stringify` and rename, link, append, stream-write or call any `write*File`
  function, or use `electron-store`;
- callers of the main-process write helpers: every exported `write*`, `save*`, `persist*` or
  `create*` function whose name ends in Json, Store, File, Settings, Vault, Ledger or Journal
  (for example `createOverrideSettingsFile`, `writeFileAtomic`), and `LibraryVault`'s `write`.

Read the module, not this file, for the format. A chapter's expansion re-runs this search over its
own modules and assigns any new one here before porting.

## Renderer localStorage

Cindy's renderer keeps preferences (theme family and mode, fonts, sidebar modes and more) in
Chromium's `Local Storage/leveldb`, which Electron holds locked while Cindy runs. The chapter that
ports each preference reads it from there and states how the port writes it back.
